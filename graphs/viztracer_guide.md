# Reading the viztracer Trace

Generated by `scripts/trace_evox.py`, opened with `vizviewer traces/evox_trace.json`.
The view has **three** layers stacked on one shared time axis.

---

## 1. The flame graph (call timeline)

Each horizontal bar is one function call.
- **Top → bottom = nesting.** The bar on top *called* the bar directly below it.
- **Width = duration.** Wide bars took longer.
- The wide dark-green `select.kqueue.control` bars are the asyncio loop **waiting for the LLM HTTP response** — that's idle wait, not CPU work. It dominates wall-clock time.
- The tall thin stacks are the real EvoX work per iteration (sample → build prompt → call LLM → parse → evaluate → add).

Click any bar → the **Current Selection** panel shows its file:line and source code.

---

## 2. Variable tracks (`log_var` counters)

These are line/step graphs plotted as their own rows, showing a value **over time**.
They come from `_install_state_tracking()` in `scripts/trace_evox.py`.

| Track | What it shows | Updated in |
|---|---|---|
| `evox/best_score` | Best solution score so far — should step upward | [[DiscoveryController._run_iteration]] |
| `evox/db_size` | Number of programs in the solution database | [[DiscoveryController._run_iteration]] |
| `evox/stagnant_count` | Iterations since last improvement — climbs, then resets to 0 | [[CoEvolutionController._should_evolve_search]] |
| `evox/best_search_score` | Best score any *search strategy* achieved | [[CoEvolutionController._should_evolve_search]] |
| `evox/num_evolutions` | How many times the outer loop has produced a new strategy | [[CoEvolutionController._switch_to_new_search_algorithm]] |

**Finding them:** they may sit above the `MainProcess` track or be collapsed.
Type a track name (e.g. `evox/best_score`) into the search bar to jump to it,
or scroll up. Click a point on the graph to read its exact value.

**How to read them together:** watch `stagnant_count` ramp up to `switch_interval`,
then a 🔀 marker fires and it resets to 0 — that's the outer loop kicking in
because the inner loop stalled.

---

## 3. Event markers (`log_instant`)

Vertical flags on the "Unnamed SliceTrack" row (the little ▲ arrows). Each marks
a moment in time. Click one to read its label.

| Marker | Means | Fired by |
|---|---|---|
| ⭐ NEW BEST | A better solution was found | [[DiscoveryController._run_iteration]] |
| ⚡ OUTER LOOP triggered | Stagnation hit `switch_interval` → search evolves | [[CoEvolutionController._should_evolve_search]] |
| 🔀 STRATEGY SWITCHED | A new search algorithm replaced the old one | [[CoEvolutionController._switch_to_new_search_algorithm]] |

## Navigation keys

| Key | Action |
|---|---|
| `W` / `S` | Zoom in / out |
| `A` / `D` | Pan left / right |
| Click bar | Show details + source |
| `M` | Mark/measure a time interval |
| `Cmd+F` / search bar | Find a function or track by name |

## Tuning the trace

| Flag | Effect |
|---|---|
| `--iters N` | Number of EvoX iterations (more = bigger file) |
| `--log-args` | Also capture function args + return values (much slower) |
| `--min-duration 100` | Drop calls faster than 100µs (less noise) |
| `--no-track-state` | Turn off the variable graphs + markers |

For line-by-line variable changes *inside* one function, use snoop instead:
`python scripts/snoop_evox.py --iters 5 --functions should_evolve`.
